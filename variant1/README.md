# variant1 — агент `quiz-test`

Smoke-агент, який проходить реєстраційний квіз **живим браузером** через Playwright MCP —
на відміну від `tests/`, де той самий сценарій зашитий у Playwright-спеку.

## Запуск

```
/quiz-test
/quiz-test https://stage.allright.com/uk/app/sign-up/long/charlie/age-range
```

Без аргументу URL береться з `tests/config/routes.ts` (`BASE_URL` + `ROUTES.QUIZ_START`).

Потрібен MCP-сервер `playwright` — він оголошений у `.mcp.json` у корені репозиторію.
Після першого підтягування конфіга сесію Claude Code треба перезапустити.

## Що робить

Проходить квіз **двічі** найкоротшим шляхом (перший придатний варіант на кожному кроці,
жодного дослідження гілок) і перевіряє два бізнес-результати по реальних відповідях бекенду:

- акаунт користувача створено;
- пробний урок заброньовано — або кроком квізу, або окремо в кабінеті після нього.

Прогін **не мокається**: акаунти і бронювання на сайті створюються справді.

## Ендпоінти навмисно не захардкоджені

Квіз під A/B-тестами, тому шляхи API і URL сторінок дрейфують. Агент визначає результат не за
конкретним шляхом, а за **моментом дії** + **origin застосунку** + **методом** + **статусом**:
перший мутуючий 2xx-запит на API застосунку, де отримався token — це створення акаунта,
після дії бронювання — це бронювання. Фактичний URL, який спрацював, потрапляє у звіт, тож
зміна ендпоінта видно як рядок «ендпоінт змінився», а не як падіння.

## Артефакти

| Файл | Поведінка |
| --- | --- |
| `result.md` | **перезаписується** щоразу: кроки, помилки, дві бізнес-умови по обох прогонах |
| `users.md` | **дописується**: id, телефон, email, ім'я кожного створеного користувача |
| `artifacts/` | скріншоти нерозпізнаних кроків, у git не потрапляє |

Більше агент нічого не змінює — ні тести, ні Page Objects, ні конфіги, ні CI.

## Definition of done

Обидва прогони пройшли, і в обох акаунт створено **і** урок заброньовано. Інакше — `FAIL`
з причиною в `result.md`.

## Відомі обмеження

- Кожен прогін лишає на стенді реального користувача і заброньований урок — чистки немає.
- Другий прогін працює на чистій сесії (куки/сховище скидаються), інакше бекенд впізнав би
  вже авторизованого користувача і повів іншою гілкою.
